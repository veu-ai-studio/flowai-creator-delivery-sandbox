# Founder-Frozen FlowAI GTM Closure Contract

Status: binding implementation checkpoint, recorded 2026-08-05.

FlowAI remains the vendor-neutral, evidence-bound orchestration and operations platform for underserved individuals and organizations. The existing product, deployed feature set, mission, accepted input classes, modes, provider selection, scoring, Self-Renewal, GTM, monitoring, portfolio, and product-governance behavior are preserved.

The existing eight-step Orchestra remains:

1. Research
2. Design
3. Build
4. Quality Audit
5. Deploy
6. Self-Renewal
7. GTM
8. Monitor

URLs may be researched, audited, compared, and synthesized, but are never modified without repository ownership and authorization. Where no owned repository exists, built output uses a controlled isolated project and returns a separate preview URL. Production promotion always requires separate authorization.

Tool selection must remain evidence-bound to current official capability evidence and runtime evidence, including task fit, target type, credentials, health, recent success, latency, cost, jurisdiction, and authorization. Durable evidence must retain considered tools, source and timestamp, selection reason, estimated and actual cost, fallback order, actual tool used, and result evidence. Researched but unwired tools are never represented as executable. Scores never override missing branches, artifacts, previews, or clearance evidence.

GTM Closure is exclusively implementation and verification of already-promised behavior. It may repair only defects that prevent existing workflows and must prove:

- one URL through eight truthful stages to a useful separate artifact and browser-accessible preview;
- multiple URLs through comparison and synthesis to a separate artifact and preview;
- a separate durable Stop lifecycle;
- truthful state across navigation, refresh, and relogin;
- registered-repository execution producing a controlled branch, artifact, and preview;
- Self-Renewal against an isolated authorized target;
- tool selection, fallback, and retained evidence;
- strict serial Windows gates and independent GO.

The registered-product non-production proof remains the next bounded integration step and is a safety proof, not a narrowing of accepted inputs. Original production evidence remains immutable. No production deployment, run, Stop test, alias change, reconciliation, or production-data mutation is authorized.

No new architecture, agents, modes, governance layers, scoring systems, marketplaces, output classes, unrelated features, product-strategy work, or separate workstream is authorized by this closure track.

Resource execution remains serial and bounded: one worker, adequate free RAM, and no heavy process outside an explicitly resumed scheduler chunk.
